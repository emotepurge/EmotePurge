## A5 – Einladung per API annehmen

Nach P7 lud der Betreiber den Bot erneut ein (Zustand `PENDING`, 17:33:53), der Bot blieb bewusst unangenommen.

- **Erwartung:** (offen) ob `PENDING` schon schreibt; ob der Bot selbst annehmen kann.
- **Befund:**
  - Solange `PENDING`: `me.editableEmoteSetIds` enthält das Set **bereits** (irreführend); `addEmote` scheitert mit HTTP 200,
    `LACKING_PRIVILEGES`, `status=403`, Meldung „you do not have permission to manage this user's emote sets“ (andere Meldung
    als bei „nicht Editor“). A `editor_of` listet den Kanal nicht.
  - Annahme: `userEditors.editor(editorId: <bot>, userId: <owner>).updateState(state: ACCEPT)` mit dem Bot-Token → `OK`,
    HTTP 200, 536 ms (17:34:16). Sofort danach in allen vier Abfragen `ACCEPTED`/manage=true; das folgende `addEmote` ging
    durch (1642 ms, Eintrag sofort lesbar).
- **Folge für G0:** Der Server kann Einladungen selbst annehmen (kein Browser, kein Betreiberhandgriff). **`editableEmoteSetIds`
  darf nicht als Schreibrecht-Signal dienen**; die Editor-Prüfung liest `state` (= `ACCEPTED`) **und**
  `permissions.emoteSet.manage`. Eine `PENDING`-Einladung ist ein eigener Zustand (nicht `not_editor`, nicht beschreibbar).
  Neue offene Entscheidung des Betreibers siehe „Ergebnis für Tor G0“.
